# 10. Тестирование

## Цель тестирования

Тестирование необходимо для проверки корректности пользовательских сценариев, работы API, сохранения данных и отображения аналитики.

## Основные направления

### Функциональное тестирование

Проверяется, что основные функции приложения выполняют ожидаемые действия.

### Интеграционное тестирование

Проверяется взаимодействие Frontend, Backend и PostgreSQL.

### Регрессионное тестирование

Повторно проверяются ранее работающие функции после внесения изменений.

### Проверка интерфейса

Проверяются отображение страниц, навигация, состояния загрузки и сообщения об ошибках.

## Чек-лист инструкций

- [ ] Список инструкций загружается.
- [ ] Можно открыть существующую инструкцию.
- [ ] Инструкция отображает принадлежащие ей шаги.
- [ ] Нельзя случайно смешать шаги разных инструкций.
- [ ] Изменения инструкции сохраняются.
- [ ] Ошибочные идентификаторы обрабатываются корректно.

## Чек-лист прогресса

- [ ] При начале шага создаётся запись прогресса.
- [ ] При начале шага `completed_at` остаётся `NULL`.
- [ ] При завершении шага `completed_at` получает дату и время.
- [ ] Повторный запрос не приводит к некорректным дубликатам.
- [ ] Прогресс одного пользователя не смешивается с прогрессом другого.
- [ ] Прогресс относится к правильной инструкции и шагу.

## Чек-лист аналитики

- [ ] Общее количество шагов соответствует данным БД.
- [ ] Пользователи считаются по уникальному `anonymous_id`.
- [ ] Начатый, но незавершённый шаг не считается завершённым.
- [ ] Завершённый шаг учитывается в статистике.
- [ ] Полностью завершившим считается пользователь, прошедший все шаги инструкции.
- [ ] В расчёт не попадают шаги другой инструкции.
- [ ] При нулевом количестве пользователей нет деления на ноль.
- [ ] Проценты не превышают 100% при корректных исходных данных.

## Чек-лист инфраструктуры

- [ ] Контейнеры собираются.
- [ ] Контейнеры запускаются.
- [ ] Backend подключается к PostgreSQL.
- [ ] Frontend доступен через Nginx.
- [ ] API доступен по ожидаемому адресу.
- [ ] Логи контейнеров доступны.
- [ ] Данные БД сохраняются после перезапуска контейнеров.

## Регистрация дефекта

Для каждого дефекта необходимо указать шаги воспроизведения, ожидаемый и фактический результат, а также приложить лог или скриншот.

## Критерии готовности

Изменение можно считать проверенным, если:

- Основной сценарий работает.
- Ошибочные входные данные обрабатываются.
- Связанные части приложения продолжают работать.
- Нет критических ошибок в логах.
- Результаты проверки зафиксированы.
