# 03. Архитектура приложения

## Общая схема

InstructionConstructorWEB использует клиент-серверную архитектуру.

```text
                 Пользователь
                      |
                      v
               Браузер / Frontend
                  Vue.js + Vite
                      |
                      v
                    Nginx
                      |
                HTTP-запросы
                      |
                      v
                Backend FastAPI
                  /         \\
                 v           v
           SQLAlchemy      SQLAdmin
                 \\           /
                  \\         /
                   v       v
                  PostgreSQL
```

Схема отражает логические компоненты. Точные правила маршрутизации зависят от конфигурации Nginx и Backend.

## Frontend

Frontend отвечает за:

- Отображение страниц и элементов интерфейса.
- Взаимодействие пользователя с инструкциями.
- Отправку HTTP-запросов к Backend.
- Отображение ответов сервера и ошибок.

## Nginx

Nginx используется как веб-сервер и точка входа для клиентских запросов. В известной конфигурации запросы с префиксом `/api/` проксируются на Backend.

Пример ранее использовавшегося правила:

```nginx
location /api/ {
    proxy_pass http://backend:8000/;
}
```

Важно: завершающий `/` в `proxy_pass` влияет на преобразование URI. При изменении маршрутов необходимо проверять соответствие путей на Frontend и Backend.

## Backend

FastAPI принимает запросы, выполняет проверку входных данных, запускает бизнес-логику и обращается к базе данных через SQLAlchemy Async.

SQLAdmin предоставляет интерфейс администрирования и аналитики.

## База данных

PostgreSQL хранит инструкции, шаги и записи прогресса.

## Поток запроса

1. Пользователь выполняет действие в браузере.
2. Frontend формирует HTTP-запрос.
3. Nginx направляет запрос в Backend.
4. FastAPI обрабатывает запрос.
5. Backend обращается к PostgreSQL через SQLAlchemy.
6. Backend возвращает ответ.
7. Frontend обновляет интерфейс.

## Принципы разделения ответственности

- Frontend не должен самостоятельно выполнять SQL-запросы.
- Backend является источником бизнес-правил.
- Данные хранятся в PostgreSQL.
- Административные операции и пользовательские API должны быть защищены соответствующими проверками доступа.
