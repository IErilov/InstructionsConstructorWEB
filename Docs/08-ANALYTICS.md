# 08. Аналитика прохождения

## Назначение

Аналитика позволяет оценивать, как пользователи проходят инструкции, сколько посетителей завершает все шаги и на каких этапах наблюдается снижение активности.

Аналитика административной панели строится на данных модели `Progress` и связанных с ней `Step`.

## Используемые данные

| Поле | Назначение |
|---|---|
| `Progress.Instruction_id` | Фильтрация прогресса по инструкции |
| `Progress.step_id` | Определение шага |
| `Progress.anonymous_id` | Подсчёт уникальных пользователей |
| `Progress.completed_at` | Определение факта завершения |
| `Step.instruction_id` | Проверка принадлежности шага инструкции |

## Основные показатели

### Общее количество шагов

Количество записей `Step`, принадлежащих выбранной инструкции.

### Количество пользователей

Количество уникальных `anonymous_id`, у которых есть записи прогресса по выбранной инструкции.

### Начали шаг

Количество уникальных пользователей, у которых есть запись прогресса по этому шагу.

### Завершили шаг

Количество уникальных пользователей, у которых для этого шага `completed_at IS NOT NULL`.

### Конверсия шага

Доля пользователей, завершивших шаг, среди пользователей, начавших его:

`Конверсия шага = Завершили шаг / Начали шаг × 100%`

Если никто не начал шаг, значение конверсии должно быть 0, чтобы избежать деления на ноль.

### Полностью завершили инструкцию

Пользователь считается завершившим инструкцию, если он завершил все шаги выбранной инструкции.

Для расчёта важно учитывать только шаги, которые действительно принадлежат выбранной инструкции.

### Процент полного завершения инструкции

`Процент завершения = Полностью завершили / Начали инструкцию × 100%`

### Средний прогресс

Средний прогресс показывает среднюю долю завершённых шагов среди пользователей, начавших инструкцию.

Рекомендуемая формула:

`Прогресс пользователя = Завершённые шаги пользователя / Общее количество шагов × 100%`

`Средний прогресс = Сумма прогресса всех начавших пользователей / Количество начавших пользователей`

Пользователи без завершённых шагов должны учитываться с прогрессом 0%. Пользователи, завершившие хотя бы часть шагов, учитываются по фактическому количеству завершённых шагов.

## Проблемные шаги

В текущей логике аналитики шаг помечается как проблемный, если конверсия ниже 60%.

Порог 60% является настраиваемым бизнес-правилом, а не универсальным критерием качества.

## Важные условия корректности

1. Начало шага не должно автоматически устанавливать `completed_at`.
2. Незавершённый шаг должен иметь `completed_at = NULL`.
3. Дата записывается только после фактического завершения.
4. При расчётах следует считать уникальных пользователей, а не количество строк, чтобы избежать двойного подсчёта.
5. Необходимо фильтровать шаги по выбранной инструкции.
6. Если инструкция не содержит шагов, процент завершения не должен приводить к делению на ноль.
7. При изменении состава инструкции нужно определить, как учитывать пользователей, начавших её до изменения.

## Интерпретация статистики

- Высокая конверсия означает, что большинство начавших шаг завершают.
- Низкая конверсия может указывать на сложность, неясность или техническую проблему шага.
- Большая разница между количеством начавших и завершивших всю инструкцию может указывать на проблемы в последовательности или объёме инструкции.

Статистика отражает зарегистрированные события и зависит от корректной фиксации прогресса на Backend.
