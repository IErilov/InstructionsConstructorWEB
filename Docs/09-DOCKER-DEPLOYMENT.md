# 09. Docker и развёртывание

## Назначение

Docker используется для запуска компонентов приложения в изолированных контейнерах. Docker Compose позволяет описать и запускать несколько сервисов совместно.

## Предварительные требования

- Docker Engine или Docker Desktop.
- Docker Compose plugin.
- Git.
- Доступ к исходному коду проекта.

## Запуск

Команды выполняются из корневой директории проекта.

### 1. Получение проекта

```bash
git clone <REPOSITORY_URL>
cd InstructionConstructorWEB
```

### 2. Настройка окружения

Проверьте `Docker-compose.yml`, Dockerfile и конфигурационные файлы. Заполните необходимые переменные окружения. Не помещайте реальные пароли и секреты в публичный репозиторий.

Названия переменных следует брать из текущего Compose-файла и Backend-конфигурации.

### 3. Сборка и запуск

```bash
docker compose -f Docker-compose.yml up -d --build
```

### 4. Проверка контейнеров

```bash
docker compose -f Docker-compose.yml ps
```

### 5. Просмотр логов

Все сервисы:

```bash
docker compose -f Docker-compose.yml logs -f
```

Отдельный сервис:

```bash
docker compose -f Docker-compose.yml logs -f backend
```

Имя сервиса `backend` приведено как пример. Используйте имя из Compose-файла.

### 6. Остановка

```bash
docker compose -f Docker-compose.yml down
```

Остановка с удалением томов:

```bash
docker compose -f Docker-compose.yml down -v
```

**Внимание:** `down -v` удаляет тома Compose и может привести к потере данных PostgreSQL. Используйте эту команду только если данные действительно можно удалить или предварительно сохранена резервная копия.

## Локальные адреса

В известной конфигурации:

- Frontend: `http://localhost`
- Backend: `http://localhost:8000`
- Swagger UI: `http://localhost:8000/docs`

Порты и маршруты необходимо сверить с Compose-файлом.

## Nginx

Nginx обслуживает Frontend и может проксировать API-запросы к Backend. Проверьте конфигурацию `location`, `proxy_pass` и базовый URL API на Frontend.

Если браузер получает 404, проверьте путь запроса и правила проксирования. Если получает 502, проверьте доступность Backend из контейнера Nginx и имя Docker-сервиса.

## PostgreSQL

Перед развёртыванием убедитесь, что:

- Backend использует правильный адрес БД внутри Docker-сети.
- PostgreSQL завершил инициализацию до подключения Backend либо Backend умеет повторять подключение.
- Данные хранятся в постоянном томе.
- Резервное копирование настроено отдельно.

## Рекомендации для production

- Не публиковать PostgreSQL наружу без необходимости.
- Использовать надёжные секреты.
- Настроить HTTPS.
- Настроить резервное копирование.
- Ограничить доступ к административной панели.
- Собирать и контролировать логи.
- Не запускать отладочный режим на публичном сервере.
