# 06. База данных

## СУБД

В проекте используется PostgreSQL. Взаимодействие с базой данных реализовано через SQLAlchemy ORM в асинхронном режиме.

## Основные сущности

По предоставленным моделям в проекте используются `Instruction`, `Step` и `Progress`.

### Instruction

Представляет инструкцию.

Подтверждённое поле:

| Поле | Назначение |
|---|---|
| `id` | Идентификатор инструкции |

Дополнительные поля необходимо сверить с актуальной моделью `Models/Instruction.py`.

### Step

Представляет отдельный шаг инструкции.

Подтверждённые поля:

| Поле | Назначение |
|---|---|
| `id` | Идентификатор шага |
| `instruction_id` | Идентификатор связанной инструкции |

### Progress

Представляет прогресс анонимного пользователя по конкретному шагу.

Подтверждённая структура:

| Поле | Тип / назначение |
|---|---|
| `Instruction_id` | UUID инструкции |
| `step_id` | UUID шага |
| `anonymous_id` | UUID анонимного пользователя |
| `completed_at` | Дата и время завершения шага; `NULL`, если шаг не завершён |

В предоставленной модели три первых поля входят в составной первичный ключ.

## Логические связи

```text
Instruction
    |
    | 1 : N
    v
   Step
    |
    | 1 : N
    v
 Progress
```

Логически один шаг относится к одной инструкции, а для шага может существовать несколько записей прогресса — по разным анонимным пользователям.

Фактические внешние ключи и ограничения необходимо проверить в ORM-моделях и схеме PostgreSQL.

## Правило завершения шага

Поле `completed_at` используется для различения начатого и завершённого шага:

- `NULL` — шаг ещё не завершён.
- Дата и время — шаг завершён.

В SQLAlchemy поле должно допускать `NULL`:

```python
completed_at: Mapped[Optional[datetime]] = mapped_column(
    DateTime(timezone=True),
    nullable=True,
    default=None
)
```

В PostgreSQL столбец также должен допускать `NULL`. Если таблица была создана раньше с ограничением `NOT NULL`, требуется миграция:

```sql
ALTER TABLE "Progress"
ALTER COLUMN completed_at DROP NOT NULL;
```

Изменение Python-модели само по себе не меняет существующую таблицу.

## Пример жизненного цикла Progress

Создание записи при начале шага:

```python
progress = Progress(
    Instruction_id=instruction_id,
    step_id=step_id,
    anonymous_id=anonymous_id,
    completed_at=None,
)
```

Фиксация завершения:

```python
progress.completed_at = datetime.now(timezone.utc)
```

Для этого примера требуется импорт:

```python
from datetime import datetime, timezone
```

Если в проекте используется другой стандарт времени, его следует применять последовательно.

## Проверки целостности

Рекомендуется контролировать:

- Существование инструкции перед созданием шага.
- Принадлежность шага указанной инструкции.
- Соответствие `Progress.Instruction_id` и инструкции, которой принадлежит `Progress.step_id`.
- Уникальность прогресса пользователя по шагу, если это соответствует бизнес-правилам.
- Корректность nullable-настройки `completed_at`.

## Миграции

Изменения схемы БД должны выполняться контролируемо — через миграции (например, Alembic, если он подключён к проекту) или документированные SQL-команды. Перед изменением production-базы необходимо создавать резервную копию.
